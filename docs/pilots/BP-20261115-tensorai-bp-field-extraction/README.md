## 1. What the chain is, and what was missing

```
pdf_evidence.extract_pdf_evidence   (pypdf, per-page text + page_text_sha256 + file sha256)
        -> business_pdf_fields.propose_pdf_fields(spectrum=...)   proposals w/ page locator
        -> business_pdf_fields.review_pdf_field_proposals          reviewer decisions, conflicts withheld
        -> business_pdf_fields.approved_pdf_fields_to_evidence_record   structured record
```

Two gaps found before the run (listed first, then filled — the only code change of this mission):

1. `business_pdf_fields` had **one** field spectrum (`trade_documents_v1`: invoice no / contract no /
   PO no / date / total). A business plan has none of those labels, so the chain would report
   "0 candidates" and it would look like a document problem instead of a coverage problem.
   → added a declared, versioned spectrum registry (`FIELD_SPECTRA`) and a `business_plan_v1`
   spectrum of 10 fields: title, version, issue date, legal disclaimer, financing stage,
   **funding amount (declared-absent)**, table label+percent rows, ratio blocks, roadmap windows,
   market references. Rules are generic table *shapes* (label line followed by a value line), not
   a list of this document's row labels.
2. A table field needs a **row key**: one percentage column is not a row. Added optional
   `subject` (captured label) to the proposal identity and made the review group accepted values by
   `(field, subject)`, so a multi-row table is neither merged nor falsely "conflicted", while two
   *different* values under one row key are still withheld.

* `criteria_v1.md` written **first**, then frozen: `criteria_freeze.json`,
  `criteria_sha256 4bd2e5208cb92500d95efb1cc1a1d3eaa8a1183a61bb24417b35707c6f3dcc5d`,
  `frozen_at 2026-11-15T15:34:01Z` ≤ `created_at 2026-11-15T15:37:43Z`. The runner refuses to run
  without a freeze that predates it, and refuses to amend a frozen criteria set.
* `python scripts/run_bp_pilot.py freeze` then `... run --pdf <private>/TensorAI_BP.pdf`
  (one command reproduces every artifact below).
* Independent second path: `scripts/bp_pilot_verify.py` re-reads the PDF with `pypdf` itself,
  re-hashes every page, and re-derives each accepted value by character-window scanning (no reuse
  of the module's regexes) — run as a separate process.
* Negative path: 4 corrupted copies (truncated body at 40 %, non-PDF bytes, zero-byte, 8-byte
  header) through the real CLI; the private copies live outside the repo.
* Regression scope: 5 adjacent test modules, 73 tests.

## 5. Notes, limits, pitfalls hit

* **Publication is desensitized by policy, not by hope.** Metric/taxonomy tokens are published
  verbatim; identity/citation values are reduced to `2-char prefix***(len, sha256[:12])`. A machine
  leak guard (C9) re-scans every page of the source against every published byte and fails the run
  if any ≥5-CJK / ≥8-Latin token of the source appears outside the whitelist → 0 leaks. It caught
  two real leaks during this mission (a brand name in the receipt's affiliation field, and
  structured-record *dict keys* that still embedded an unmasked subject) — both fixed, both now
  covered by `tests/test_bp_pilot_artifacts.py`.
* **Offsets must address the stripped value.** The ratio-block rule's capture group swallowed a
  trailing newline, so locators pointed one character past the value (3 of 22 fields). Fixed in the
  module and pinned by `test_every_locator_addresses_exactly_its_value`.
* **A publisher is not a row key.** Keying citations by publisher alone put two same-publisher
  reports into a genuine conflict; the review correctly withheld them instead of merging. The rule
  now keys a citation by `publisher: title`, and the conflict path is pinned by a test.
* `table_label_percent` consumes only the first percentage line under a row label, so in the
  4-column revenue table it returns one cell per row; the complete rows come from `ratio_block`.
  Recorded as a `defect` record (`accepted_limitation`), not hidden.
* `market_reference` requires a parenthesised publication year, so 2 of 5 reference lines
  (published without a year, and one with a wrapped URL) produce no proposal. Recorded as a
  `defect` record. Field coverage still counts the field as extracted (3 proposals) — that is why
  "field extracted" is not the same claim as "table complete".
* `reportlab` was installed during this mission so the pre-existing `tests/test_pdf_evidence.py`
  could be collected (it was previously an import error). Declared, not silently assumed.
* Regex label/table-shape extraction is not OCR and not table reconstruction; the plan's tables are
  line-flattened by the PDF text layer, which is exactly what this rule set exploits and also its
  failure mode.
* One document, one language, one layout: the coverage numbers are **this document's** numbers.
